# Glossário de Domínio

Este glossário padroniza os termos e conceitos chave utilizados no projeto `spec-driven-secure-development` para evitar ambiguidade e garantir uma comunicação clara entre humanos e IAs.

## Termos Comuns:

- **Especificação (Spec):** Documento detalhado que descreve o comportamento esperado de um sistema ou funcionalidade ANTES de qualquer implementação.
- **Agente de IA (AI Agent):** Entidade de software (LLM ou outro) que interage com o sistema para gerar código, documentação, revisões, etc., com base em diretrizes.
- **Grill Session:** Processo interativo onde o Agente de IA faz perguntas para refinar e clarificar uma especificação antes de finalizá-la.
- **Human-in-the-Loop (HITL):** Tarefas que exigem revisão, aprovação ou intervenção humana direta.
- **Autonomous AI Tasks (AFK):** Tarefas que podem ser executadas autonomamente pelo Agente de IA sem supervisão humana direta.
- **Shift-Left Security:** Abordagem de segurança onde as práticas de segurança são integradas desde as fases iniciais do ciclo de desenvolvimento, em vez de serem adicionadas no final.
- **ADR (Architecture Decision Record):** Registro de uma decisão arquitetural significativa, incluindo o contexto, a decisão tomada e as alternativas consideradas.
- **SAST (Static Application Security Testing):** Análise estática de código para identificar vulnerabilidades de segurança.
- **SCA (Software Composition Analysis):** Análise de dependências de software de terceiros para identificar vulnerabilidades conhecidas.
- **NFR (Non-Functional Requirement):** Requisito que especifica critérios para avaliar a operação de um sistema, em vez de comportamentos específicos (ex: performance, segurança, usabilidade).
- **Definition of Done (DoD):** Conjunto de critérios que devem ser satisfeitos para que um incremento de software seja considerado completo.
- **OWASP Top 10:** Lista das dez vulnerabilidades de segurança mais críticas para aplicações web, publicada pela Open Web Application Security Project.
- **RFC (Request for Comments):** Proposta formal de mudança ou nova funcionalidade, aberta para discussão e feedback antes da aprovação final.
- **Harness:** Estrutura de diretório e arquivos para concentrar contexto, decisões, regras, vocabulário e histórico operacional do sistema, tornando o conhecimento organizado e rastreável.
